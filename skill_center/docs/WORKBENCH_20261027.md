# 第一版算法与绘图增量 · 2026-10-27

本次仅扩展用户负责的独立 Skill 中心，复用服务器原有 `bioflow_ml` 的算法接口与实现。总前端、旧 Skill 模块、原算法实现及其他三个业务板块不作改动。新页面使用已有布局、登录与样式体系。

## 入口与使用

- `/algorithms`：已有算法目录、详情、展示设置、参数版本、验证及发布。首批支持 PCA、K-means、随机森林真实运行，其他 7 个已有算法仅列目录。
- `/plots`：分组散点、数值矩阵热图、分组箱线与散点、相对丰度堆叠、特征重要性、流程示意图 6 类模板。
- `/runs`：算法、示例验证与绘图运行记录。
- 原 `/skills`、业务板块、导入、编辑和版本功能保留。新增 6 个本地绘图模板 Skill，包含正文、脚本、参数模板、合成示例 CSV 与示例图，可从绘图页查看或按原流程导出完整包。

算法使用：选择一个可运行算法 → 上传数据或使用合成示例 → 确认样本标识、标签或展示分组、数值特征和参数 → 开始运行 → 查看图形、指标、表格及日志 → 下载完整结果。

数据支持 CSV、TSV、制表符 TXT、XLSX（第一个工作表），最多 10 MB、20000 行、500 列、200 万单元格。样本 × 特征矩阵必须包含至少两个数值特征，样本标识完整且唯一；分类标签不能缺失。缺失或非数值特征会明确报错，不自动补齐。原始上传哈希和转为 CSV 后的哈希分别记录。

结果提供 PNG、SVG、PDF、CSV 及 JSON 记录，固定算法版本、源码快照、随机种子、参数与依赖版本。PCA 和聚类结果可重绘散点或热图；随机森林提供重要性图和结果表。重绘使用已有结果数据并新建记录，不重新执行原算法，不覆盖旧图。

## 增量维护

展示设置可以修改名称、用途和类别，并启用或停用已发布算法。保存参数新版本不会改写旧版本；新版本需通过合成示例验证后发布。已发布旧版本可恢复为当前发布，历史任务仍对应当时使用的版本。

“新增算法配置”复用已有实现，仅另存配置；“导入算法包”接入新源码。可下载 `algorithm-package.zip` 示例，根目录包含 `algorithm.json` 与 `algorithm.py`。算法类继承既有 `BaseAlgorithm`，接收 `MLInput` 并返回 `AlgorithmResult`。清单声明名称、版本、入口、任务及参数类型、默认值和范围。

源码导入仅保存，不执行；点击验证后由独立工作进程运行合成示例，成功后才能发布和选择使用。更新已有源码包时清单名称必须保持一致，另存不可变版本。首版不提供在线 Python IDE，也不自动安装新包的依赖。

## 科研与执行边界

- 所有示例数据均为合成数据，不是研究发现。示例验证通过只证明已在当前环境跑通。
- 沿用原算法的交叉验证和结果定义；未增加调参搜索、外部队列验证或重复测量分组交叉验证。
- 随机森林的重要性来自全量拟合，不能视作因果机制；不将全量模型概率作为折外 ROC 数据展示。
- 聚类散点是额外 PCA 投影，聚类本身仍在用户选定的特征空间计算。
- 箱线图保留观测点，不自动生成显著性星号。堆叠图明确将所选特征的样本内总和归一为 100%，导出对应作图数据。
- 尚未接入模型自动调用、任务自动编排、批量训练或大型流程编辑器。原有第三方 Skill 的运行状态不因新增模板而改为已验证。
- 模板 Skill 保存可导出的脚本与说明，工作台运行受控的固定模板实现。单独编辑 Skill 脚本不会热替换工作台执行代码；绘图设置记录模板实现的版本与 SHA-256。
- API 与科学计算分开运行，同时最多两个工作任务，等待和运行合计最多十二个；设置 CPU、内存、文件大小和墙钟时限。独立进程与资源限额不等于操作系统安全沙箱，源码包限经过审查的自有算法。

## 部署与运维

应用仍为 `/home/xh/BioFLow/skill_center`，仅监听 `127.0.0.1:18120`，账号及现有本机转发方式不变。算法库通过只读复制生成带哈希的源码快照，保存在本中心 `storage/workbench/sources/`，原库未被改写。

科学依赖安装到本项目 `.ml-venv`，不修改共享环境或原算法环境：

```bash
cd /home/xh/BioFLow/skill_center
python3 -m venv .ml-venv
.ml-venv/bin/python -m pip install -r requirements-ml.lock
.venv/bin/python deploy/setup_workbench.py --source-root /home/xh/BioFLow/bioflow_ml
.venv/bin/python deploy/manage.py start
```

`setup_workbench.py` 可重复执行：复用相同源码快照和已存在的内置记录，不覆盖已有展示设置、发布指针或已有同名绘图 Skill。模型调用仍未实现。数据库 schema 升为 3，只增加算法、版本、数据集、运行四张表，既有 Skill 内容格式保持不变。

可用 `SC_ML_PYTHON` 指定隔离科学环境。`SC_FRONTEND_DIR` 用于隔离验收前端；正式部署采用原 `frontend/dist`。服务重启会将未完成任务标为中断，需手动重新提交，不自动恢复执行。
